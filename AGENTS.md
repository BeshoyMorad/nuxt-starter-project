# Project instructions

<!-- Shared by Codex, Gemini CLI, Cursor, and Claude Code (CLAUDE.md imports this file). Keep it tool-neutral and under 200 lines. -->

## Stack

Nuxt 4 (SSR, `srcDir: src/`), Vue 3.5, TypeScript, Tailwind CSS v4 with reka-ui primitives, Pinia (`@pinia/nuxt`), TanStack Vue Query and Vue Table, vee-validate + Yup, Axios, `@nuxtjs/i18n` (`en`, `ar`), `@nuxt/image`, vue-sonner, Vitest + MSW. Package manager: pnpm.

## Commands

- Dev: `pnpm dev` · Build: `pnpm build` · Typecheck: `pnpm type-check` · Lint: `pnpm lint` (`pnpm lint:fix`) · Format: `pnpm format`
- Unit: `pnpm test:unit --run <file>` · Locale aggregators and types: `pnpm locales:types` (runs inside `type-check`)
- Everything at once: `pnpm verify`. Run it only when asked.
- Known: `useMultiStepForm.spec.ts` and `StarterDashboard.spec.ts` fail with `defineStore is not defined` because plain Vitest has no Nuxt auto-imports. Judge a change by the specs that can load.
- Verify a change with lint on the changed files, typecheck, and the relevant spec only. Never run the full suite unless asked. `pnpm test:unit` alone starts watch mode and hangs, so always pass `--run`.

## Architecture

- **Nuxt 4 SSR.** Everything must be SSR-safe: no `window`/`document`/`localStorage`/`navigator` at module scope or at the root of `<script setup>`. Use `onMounted`, `import.meta.client`, or a `*.client.ts` plugin.
- Routes are file-based (`src/pages/`). Page files stay thin and import the module page. Guards are route middleware in `src/middleware/` (`auth.global.ts`, `permission.ts`).
- Auto-imports are on: `defineStore`, `useCookie`, `navigateTo`, `useI18n`, and friends need no import. Plugins in `src/plugins/` set up Vue Query, dayjs, Yup, theme, and locale.
- Feature code lives in `src/modules/<feature>/`. `src/modules/doc/` is the showcase; `src/pages/examples/` are demos that call `fetch` directly and must not be copied.

## Golden rule: reuse before you write

Before creating any component, composable, or util, search for an existing one (`src/components/ui`, `src/components/form`, `src/components/data-table`, `src/composables/`, `src/utils/`, `src/lib/`). If one exists, use it. If you believe a new primitive is truly needed, say so and ask first.

- Translations: `src/locales/{en,ar}/<namespace>.json`, aggregated by `src/locales/en.ts` and `ar.ts` · i18n config: `src/i18n.config.ts`, `i18n` block in `nuxt.config.ts`

## Non-negotiables (details in `.claude/rules/`)

- **RTL-first.** Logical Tailwind classes only (`ms-* me-* ps-* pe-* start-* end-* text-start text-end`). Never `ml- mr- pl- pr- left- right- text-left text-right`.
- **No hard-coded UI strings.** Every label goes in `en` and `ar` JSON, used through `t()`.
- **Registries, not literals.** Query keys from `queryKeys`, URLs from `apiRoute()`, test ids from `TEST_IDS` (`data-test-id`), colors from the token file, route names from `paths`.
- **Server state in Vue Query, client state in Pinia.** Never copy API data into a store. No manual `try/catch` toasts.
- **Strict TypeScript.** No `any`, `interface` over `type`, `import type`, `@/` alias instead of `../`. Files under 300 lines.

## Nuxt gotchas

- Do not add a Vite-style `import.meta.glob` locale loader. `@nuxtjs/i18n` merges `files` at the root without namespacing, so `en.ts` / `ar.ts` aggregate the namespace JSON files (regenerated by `generateLocaleTypes` on build and on locale file add/remove).
- Read the locale from `nuxtApp.$i18n`. A plugin whose return type depends on `$i18n` can hit `TS7022`; annotate types explicitly. A deep merged message tree can hit `TS2589` on `t`; cast locally through `unknown`.
- `.husky/` has no `pre-commit` file here yet, so lint-staged does not run on commit. Run `pnpm lint` before pushing.

## Automated checks

- Hooks in `.claude/hooks/` (wired for Claude Code in `.claude/settings.json`, Gemini CLI in `.gemini/settings.json`, Codex in `.codex/hooks.json`, Cursor in `.cursor/hooks.json`): after each edit they run Prettier, RTL / convention / en-ar locale-parity checks, and ESLint on the file. Before edits they block lockfiles, `.env`, `*.generated.ts`, and build output. Before shell commands they block `vitest` without `--run`, force push, `--no-verify`, and `git reset --hard`. Fix what they report before moving on.
- No hooks in your tool? After editing, run `.claude/hooks/post-edit.sh <file>...` yourself and fix what it prints.
