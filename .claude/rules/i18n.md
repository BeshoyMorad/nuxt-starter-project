# i18n (`@nuxtjs/i18n`)

- Messages are JSON only, in `src/locales/{locale}/{namespace}.json`. Filename is the key prefix: `en/common.json` → `t('common.save')`.
- Supported locales: `en`, `ar`. Add both files for every namespace.
- `src/locales/en.ts` and `ar.ts` are thin aggregators. They import each namespace file and expose it under its name. `nuxt.config.ts` loads them per locale (`i18n.locales[].file`), so a locale is fetched when it is needed.
- After adding a namespace file, import it in both `en.ts` and `ar.ts`. The message types come from `typeof en` in `schema.d.ts`, so a missing import also breaks `t()` key checking.
- Do not put `locales/` next to components or modules. Do not store messages in `.ts` other than the two aggregators. Do not use SFC `<i18n>` blocks for app copy.
- JSON has no extra wrapper. `common.json` is `{ "save": "Save" }`, not `{ "common": { "save": "Save" } }`. There are no root-level messages: put one-off strings under a namespace (for example `common.welcome`).
- `t()` / `$t()` only. Hard-coded UI strings belong in a JSON file first.
- The chosen locale is stored in a cookie so the server renders it on the first request. `src/plugins/locale.ts` keeps `<html lang dir>` and Dayjs in sync. Browser-language detection is off (`detectBrowserLanguage: false`).
- i18n Ally: `.vscode/settings.json` (`{locale}/{namespace}.json`, `namespace: true`). Do not change folder shape without updating that config.
